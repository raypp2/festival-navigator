iOS playback probe

Answers one question our laptops cannot: on THIS phone, does a gesture-unlocked embed keep playing when we load a different artist into it?

1 · Baseline — no gesture

Mounts the embed and asks it to play with nobody touching anything. On iOS this should be REFUSED. What matters is which events it fires while refusing.

not run

2 · With a real gesture

Same embed, but play is called from inside your tap. This should work — and it is the tap that unlocks the element for everything after it.

not run

3 · The real question — load a different artist into the SAME element

No new iframe, no new tap. If audio keeps going, the app's approach is right and the bug is in our wiring. If it stops, the approach cannot work on iOS and we need a different one.

not run

4 · SoundCloud and Spotify — load, then ask explicitly

Step 3 never calls play(). The app does. SoundCloud: it loads, waits for the callback, then calls play() itself. Spotify: loadArtist calls loadUri() and play() on the very next line — this runs exactly that, and if it stays silent, calls play() again on a delay with no new tap. That second try is the whole point: it separates the app races the load from the unlock did not survive it, which are different bugs with different fixes.
