Sample player — v2
Rebuilt from the player research
Replaces the placeholder sample block in every mockup. Behaviour, tab order and stage sizes are taken from the working harness — the three embeds have fixed shapes and we design around them, not the other way round. Mockup only: the stages here are drawn, not live embeds.
What the research changed
YouTube leads now
Tab order is YouTube → SoundCloud → Spotify. The top YouTube hit is usually the full festival set — v1 defaulted to SoundCloud, which is the weaker first guess.
Auto-pick, then swap
Every source mounts its best result and starts. Alternates sit next to the stage as a numbered list — no search box, no dead ▶.
The source is remembered
Last source used persists across artists and across reloads. If an artist lacks it, fall back to the highest-priority source they do have.
One player, always
Switching source, switching artist, closing the sheet — each tears the previous player down first. Two things never sound at once.
Stage sizes are fixed
YouTube 16:9 · SoundCloud 166px · Spotify 352px. The panel height changes per tab — that's expected, don't lock it.
Spotify brings its own list
Its embed already lists top tracks, so we draw no alternates pane for it — just the preview caveat.

YouTubedefault
Cached search.list per artist gives 3 verified sets; the keyless IFrame player plays the first. Alternates are the other cached hits, labelled by festival and year — that label is what makes the list worth tapping.
SoundCloud
Widget API embeds the artist's profile; getSounds() returns the real posted tracks live, so the list is never stale. Cap at 6. Public tracks play in full with no session. Attribution required.
Spotify
The studio sound, not the set. Its embed carries its own top-tracks list, so our alternates pane collapses to one line. Signed out or Free = 30-sec preview — the chip on the stage says so, always.
Tabs are presence-driven
A tab only renders when that artist resolved that source. Two sources = two tabs. None = the block collapses to the one-liner below.
02 · Compact — inside a card
The swipe deck can't hold a 16:9 stage, so the card carries the same tabs over a now-playing row, with the first three alternates listed underneath — open by default. Three rows is small enough that hiding them behind a control only makes the swap undiscoverable; if a source has more, the extra rows are reachable in the sheet. This is what replaces the old three-chips-and-a-waveform block.

Same ▶, same instance
The card's play button and the artist page target one player. Raising the sheet from a card hands over the running source and position rather than starting a second one.
Swiping stops it
A decision — pick, must or pass — tears the player down as the card leaves. The next card mounts on the remembered source but does not auto-play; sampling stays a deliberate tap in the deck.
The stage never lies
Whatever is playing has to look like itself: YouTube is a 16:9 frame — full size where there is room, an 82×46 thumbnail with its own progress bar in a card — SoundCloud is the waveform row, Spotify its list. A video source never hides behind a round play button.
Row count
Three rows on a card, six in the sheet — always visible, never collapsed. Spotify shows none: its list lives inside its own embed, so the card falls back to the now-playing row and the preview badge.
03 · Desktop — stage beside the list
At 1120px and up the alternates move to a right-hand rail so the stage keeps the width. Between 960 and 1120 the pane stays single-column — a bigger player beats a side-by-side list. Spotify spans full width at every size.

For engineering
Tab priority ['yt','sc','sp'] doubles as the fallback order. Persist the last source under one key and honour it per artist when present. YouTube needs a secure context — over plain HTTP the player throws 150/153 while the other two keep working, so dev builds must run on localhost or HTTPS. Cache the YouTube search per artist (100 units a call against a 10k/day quota); SoundCloud's list is free to fetch live.
