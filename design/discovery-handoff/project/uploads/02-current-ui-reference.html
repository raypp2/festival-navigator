Current UI reference

This is the visual language Discovery has to live inside. Everything below is rendered with the production token values and the real aura math — not a redraw. Open 01-design-tokens.css alongside it.

The one thing to understand before designing: an artist card's visual budget is already fully spent. The background is the crew's picks, the bottom-right corner is who picked, the bottom-left is notes + Spotify. Genres, a “why we recommended this” reason, and a “passed” state have nowhere obvious to go — and the card a recommendation most needs to mark is the flat, unpicked one, which is deliberately the plainest thing on screen.

Artist card — pick states

One person (colour slot 0, hue 10°). Levels 1–3 render the same colour at alpha .5 / .75 / 1.0. “Must” is level 4 — same full alpha, but it sorts innermost and is marked with a lettered pill instead of a tick.

The aura — a crew converging

Each person who picked adds one radial-gradient layer in their own colour, anchored at a rotating corner (20% 120%, 85% -20%, -15% 30%, 115% 70%). Musts layer first/innermost. This blend is the crew-convergence signal — the single most distinctive thing in the product. White stroke = you; everyone else gets a tint of their own hue.

The crew board — 24 colours

Members are identified by colour + initial, never a photo. Slots are assigned lowest-free and are stable for a member's life; the order is hue-spread so people who join near each other stay visually far apart. You are the only white-stroked member.

Rules with teeth

The festival accent (--fest, a per-festival RGB) appears in exactly four places: the festival name, the active day tab, stage headers, and the current-festival border in Settings. Nowhere else. Anything else that wants to look “selected” or “ours” uses brand violet. The accent once crept into seven places — including the loader shown while a crew was still being created, i.e. wearing a festival's colour before a festival had been chosen — and had to be pulled back.
44px minimum touch target on every button. It is applied to button as an element, not to a list of selectors — the naming was the bug once, and every control added after the named six silently got nothing. If you add a control, it inherits the floor by being a button.
Motion can never carry meaning. prefers-reduced-motion and a low-power mode kill every animation and hide the grain. If a state is only legible while something is moving, it is invisible to a real user in a field on 4% battery.
